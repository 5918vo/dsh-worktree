## 一、隔离环境与初始事故

### 1. 初始隔离失败（不计为产品缺陷）

第一次准备测试环境时，仅设置 `DSH_HOME` 就认为台账会被隔离。实际上 `Store` 的默认目录来自 `src/store.ts` 的 `stateDir()`：

```ts
join(homedir(), '.dsh', 'worktree-tasks')
```

构造参数 `dir = stateDir()` 与 `DSH_HOME` 无关，因此上一次 pi 测试把临时项目 `e2e-1123`（`id 075bd2b9-6a1b-4095-baba-5a59be034cfe`）和临时 repo 路径写进了真实台账（`~/.dsh/worktree-tasks/projects.json`、`recents.json`）。

精确恢复：

- 用临时脚本只删除上述 `e2e-1123` 项目和 `recents.json` 中的临时 repo 路径；真实 `tasks.json` 与备份逐字一致。
- 当时没有发布任务、没有创建 worktree。
- 本轮开始前再次只读核对真实台账：`projects.json` 466B（仅 `dsh-worktree` 和旧 `repo`）、`recents.json` 312B、`tasks.json` 13551B（Nov 22），均无 `e2e-1123` 或临时根路径；`~/.dsh/worktrees` 不存在。

### 2. 本轮采用的隔离方式

不修改生产 `Store` 行为，也不声称 `DSH_HOME` 会自动隔离台账。做法是测试专用模块 + 显式目录：

1. 复制已构建插件到测试根下的 `plugin-e2e`（`dist/index.js`、`dist/client.js`、locale、icon、`cordis.patch.yml`、`package.json`）。
2. 只在该副本的 `dist/index.js` 中替换 `stateDir()`：仅当 `DSH_WORKTREE_STATE_DIR` 等于测试根下的 `worktree-tasks` 时返回该目录，否则抛错。生产仓库文件未改。
3. 把 `profiles/web/node_modules/@5318vo/dsh-worktree` 指向 `plugin-e2e`，并让 `profiles/web/cordis.patch.yml` 使用相同包名，避免 profile patch 因 name 不匹配被跳过。
4. profile 配置显式设置 `dirName: <测试根>/worktrees`、`branchPrefix: dsh-e2e/`、`gitPath: git`。
5. 预置隔离台账（空 projects/tasks/recents/criteria/templates + `.migrated-v2`），避免旧台账迁移。

验证结果：

- `dsh --dump-config` 显示 patch 已应用，无 name mismatch 警告。
- `/dsh-worktree/api/config` 返回 `dirName` 为测试根 `worktrees`。
- 新建任务的 worktree 实际落在 `C:\...\dsh-worktree-e2e-0V27sz\worktrees\...`，不是共享 `~/.dsh/worktrees`。
- 整个测试期间共享台账的 `projects.json` / `recents.json` / `tasks.json` 内容和 mtime 均未变化，共享 `worktrees` 目录不存在。

## 三、发现的问题

### P2-1 项目概览的检查器覆盖项目报告按钮（可用性）

- 现象：1251×1222 视口下，项目概览右侧 `<aside class="dshw-inspector">` 覆盖「下载报告 / 复制报告」区域。Playwright 指针点击被 aside 拦截，只能先用 Tab 聚焦再按 Enter。
- 影响：鼠标用户可能无法下载/复制项目报告；检查器没有关闭入口。
- 证据：点击「下载报告」返回 `element intercepts pointer events`；键盘 Enter 成功下载，内容正确。
- 建议：项目视图为 inspector 预留右侧空间，或在项目概览隐藏检查器，或给 aside 提供折叠/关闭。

### P2-2 无会话的手工任务遇到基线冲突时没有内置同步入口（功能缺口）

- 现象：E2E-2 在 E2E-1 合并后直接合并被阻止，提示「基线有新提交，且与任务改动存在冲突。建议先让 Agent 同步基线。」
- 该任务按测试要求未启动真实模型会话，UI 没有提供「同步基线」按钮；只能进入 worktree 手工 `git merge main` 并解决冲突。
- 影响：不使用 Agent 的纯手工 worktree 任务在冲突路径上被文案指向一个不存在的会话动作，用户需要自己知道去 worktree 操作。
- 建议：在冲突阻止态提供「在 worktree 中同步基线」的明确说明或按钮；或在检测到无会话时给出可执行的手工命令。
- 备注：手工同步后合并、清理均正常。

### P3-1 发布弹窗底部路径预览忽略运行时 `dirName` 配置（显示问题）

- 现象：项目未设置 `dirName` 时，发布弹窗预览固定显示 `~/.dsh/worktrees/<project>/<auto>`；实际 worktree 使用 profile 配置的 `dirName`（测试根 `worktrees`）。
- 影响：自定义 `dirName` 的用户看到的路径与实际落盘不一致。默认配置下两者相同，因此生产默认路径下不易暴露。
- 证据：首次发布 E2E-1 预览为 `~/.dsh/worktrees/...`，实际目录在测试根 `worktrees`；给项目显式设置 dirName 后预览变为正确路径。
- 建议：预览使用服务端计算出的 effective dirName（`project.dirName || config.dirName`），而不是只读项目字段。

### 观察项（未定性为缺陷）
