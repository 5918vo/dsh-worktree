## 一、隔离环境与初始事故

### 1. 初始隔离失败（不计为产品缺陷）

第一次准备测试环境时，仅设置 `DSH_HOME` 就认为台账会被隔离。实际上 `Store` 的默认目录来自 `src/store.ts` 的 `stateDir()`：

```ts
join(homedir(), '.dsh', 'worktree-tasks')
```

构造参数 `dir = stateDir()` 与 `DSH_HOME` 无关，因此上一次 pi 测试把临时项目 `e2e-1123`（`id 075bd2b9-6a1b-4095-baba-5a59be034cfe`）和临时 repo 路径写进了真实台账（`~/.dsh/worktree-tasks/projects.json`、`recents.json`）。

精确恢复：

- 用临时脚本只删除上述 `e2e-1123` 项目和 `recents.json` 中的临时 repo 路径；真实 `tasks.json` 与备份逐字一致。
- 当时没有发布任务、没有创建 worktree。
- 本轮开始前再次只读核对真实台账：`projects.json` 466B（仅 `dsh-worktree` 和旧 `repo`）、`recents.json` 312B、`tasks.json` 13551B（Nov 22），均无 `e2e-1123` 或临时根路径；`~/.dsh/worktrees` 不存在。

### 2. 本轮采用的隔离方式

不修改生产 `Store` 行为，也不声称 `DSH_HOME` 会自动隔离台账。做法是测试专用模块 + 显式目录：

1. 复制已构建插件到测试根下的 `plugin-e2e`（`dist/index.js`、`dist/client.js`、locale、icon、`cordis.patch.yml`、`package.json`）。

3. 把 `profiles/web/node_modules/@5318vo/dsh-worktree` 指向 `plugin-e2e`，并让 `profiles/web/cordis.patch.yml` 使用相同包名，避免 profile patch 因 name 不匹配被跳过。
4. profile 配置显式设置 `dirName: <测试根>/worktrees`、`branchPrefix: dsh-e2e/`、`gitPath: git`。
5. 预置隔离台账（空 projects/tasks/recents/criteria/templates + `.migrated-v2`），避免旧台账迁移。

验证结果：

## 三、发现的问题

### P2-1 项目概览的检查器覆盖项目报告按钮（可用性）

- 现象：1251×1222 视口下，项目概览右侧 `<aside class="dshw-inspector">` 覆盖「下载报告 / 复制报告」区域。Playwright 指针点击被 aside 拦截，只能先用 Tab 聚焦再按 Enter。
- 影响：鼠标用户可能无法下载/复制项目报告；检查器没有关闭入口。
- 证据：点击「下载报告」返回 `element intercepts pointer events`；键盘 Enter 成功下载，内容正确。
- 建议：项目视图为 inspector 预留右侧空间，或在项目概览隐藏检查器，或给 aside 提供折叠/关闭。

### P2-2 无会话的手工任务遇到基线冲突时没有内置同步入口（功能缺口）

- 现象：E2E-2 在 E2E-1 合并后直接合并被阻止，提示「基线有新提交，且与任务改动存在冲突。建议先让 Agent 同步基线。」
- 该任务按测试要求未启动真实模型会话，UI 没有提供「同步基线」按钮；只能进入 worktree 手工 `git merge main` 并解决冲突。
- 影响：不使用 Agent 的纯手工 worktree 任务在冲突路径上被文案指向一个不存在的会话动作，用户需要自己知道去 worktree 操作。
- 建议：在冲突阻止态提供「在 worktree 中同步基线」的明确说明或按钮；或在检测到无会话时给出可执行的手工命令。
- 备注：手工同步后合并、清理均正常。

### P3-1 发布弹窗底部路径预览忽略运行时 `dirName` 配置（显示问题）

- 现象：项目未设置 `dirName` 时，发布弹窗预览固定显示 `~/.dsh/worktrees/<project>/<auto>`；实际 worktree 使用 profile 配置的 `dirName`（测试根 `worktrees`）。
- 影响：自定义 `dirName` 的用户看到的路径与实际落盘不一致。默认配置下两者相同，因此生产默认路径下不易暴露。
- 证据：首次发布 E2E-1 预览为 `~/.dsh/worktrees/...`，实际目录在测试根 `worktrees`；给项目显式设置 dirName 后预览变为正确路径。
- 建议：预览使用服务端计算出的 effective dirName（`project.dirName || config.dirName`），而不是只读项目字段。

### P2-1 项目概览 Inspector 覆盖验收报告按钮 / 没有关闭入口

根因（三处叠加）：

1. `src/client/project-detail.ts` 的 `<aside>` 用的是旧类名 `dshw-inspector`，而工作台所有断点规则（`src/client/styles/workbench.ts`）都只匹配 `.dshwd-inspector`，因此项目视图完全不参与容器查询：≤980px 的「隐藏/抽屉」和 ≤720px 的「面板」规则都没生效。
2. `project-detail.ts` 的根节点 class 是写死的 `dshw-detail-inner dshw-stage-grid`，从不追加 `dshw-inspector-hidden`；顶栏 `◨` 按钮只改了 board 状态，项目视图的面板仍挂在页面上 —— 这就是「检查器没有关闭入口」。
3. 堆叠布局下 `.dshw-board .dshwd-management .dshw-stage { min-height: 100% }` 让 stage 的网格行占满面板高度，而 stage 内容比这个行高更高，超出的部分溢出到行外；排在 stage 盒子之后的 inspector 行正好压在这段溢出内容上。实测 1025×900（board 746）下 stage 盒子高 780、验收报告卡片从 774 开始、inspector 从 780 到 900：卡片与面板重叠 42634px²，两个按钮（y≈830）位于面板矩形内，`document.elementFromPoint` 命中的是 panel 而不是按钮 —— 与第一轮 Playwright 报的「intercepts pointer events」一致。

修复（沿用既有容器查询 / 抽屉设计，没有用「永久隐藏 Inspector」规避）：

- 新增 `src/client/detail-layout.ts` 的 `stageGridClass(inspectorHidden)`，项目详情根节点改用它，`◨` 开关现在真正收起面板。
- `src/client/styles/workbench.ts` 增加三条项目专属规则：隐藏态折叠为单列、隐藏态 `display:none`、以及 `.dshw-stage { min-height: auto }` 让 stage 行按内容撑开（单行时网格仍会把行拉伸到面板高度，1901px 下实测 stage 1100 = 网格高度，行为不变）。
- 面板始终是「宽屏右列 / 窄屏堆叠块」，没有任何 `position: absolute/sticky` 覆盖（单测里有断言）。

真实浏览器证据（Chrome DevTools MCP，鼠标点击，非 JS 合成）：

| 视口 | 布局 | 结果 |
|---|---|---|
| 1901×1100（board 1622，两列 1066+284） | Inspector 打开 | 鼠标点击「下载报告」→ 生成 `project-fix-verify-1123-20261123-1633.md` |

### P2-2 无会话手工任务遇到基线冲突时引导到不存在的 Agent 动作

根因：`src/client/action-gate.ts` 的冲突提示固定用 `mergePreviewConflictHint`（「建议先让 Agent 同步基线」），而 `src/client/inspector.ts` 的同步按钮在 `!task.sessionId` 时是**禁用**状态、title 为「先创建会话后才能同步基线」；`src/client/board/use-board-actions.ts` 的 `runSyncBaseline` 也会直接 `say(t.syncNoSession)` 返回。也就是说无会话任务被指向一个它不可能拥有的能力。

修复（最小一致方案，未把同步变成自动执行、未放宽任何冲突/主仓库检查）：

- `src/client/review-surfaces.ts` 新增纯函数 `manualSyncCommand(task)`：返回 `cd "<worktreePath>"` + `git merge <baseBranch|main>`（分两行，避免旧 PowerShell 不支持 `&&`）；无 worktree 时返回空串。
- `src/client/inspector.ts`：无会话时把禁用按钮换成可用的「复制同步命令」（`t.syncManual`），下方增加一行常显说明（`t.syncManualHint`），`onClick` 走 `props.onCopy(syncCommand)`；有会话时行为完全不变（仍发 Agent 指令）。
- `src/client/action-gate.ts`：`task.sessionId ? t.mergePreviewConflictHint : t.mergePreviewConflictManualHint`（后者明确写「该任务没有会话，请在 worktree 中手动合并基线（检查器里有可复制的命令），完成后重新预检」）。
- i18n：`zh.json` / `en.json` 各加 3 个键，键集一致（`check:locale` 通过）。

真实浏览器证据（任务 96aa88c3，无会话，待验收，`5c96ff9..78564b3`）：

1. 修复后任务页「阻塞项」与「直接合并」的 title 都显示手工同步文案；检查器里是可点的「复制同步命令」+ 说明行，不再是禁用按钮。

### P3-1 发布弹窗路径预览忽略运行时 `dirName`

根因：`src/worktree-layout.ts` 的 `worktreePreviewRoot(project)` 只读 `project.dirName`，缺失时回退常量 `DEFAULT_WORKTREE_DIR`；而服务端容器里 `ctx.config.dirName` 是生效值（`src/runtime/types.ts` 的 `effectiveConfig`）。同时 `src/client/board.ts` 把 `cfg: null` 传给项目详情，导致设置项占位符也只显示默认值。

修复（统一到一条规则，前后端复用同一函数）：

- `src/worktree-layout.ts`：新增 `effectiveDirName(project, fallbackDirName)`（项目覆盖 → 运行时配置 → 默认），`worktreePreviewRoot(project, fallbackDirName?)` 改用它，保留外部绝对根（`~` / `/` / `\` / 盘符）与旧相对目录两种布局的分支。
- `src/runtime/types.ts`：`effectiveConfig` 改用同一个 `effectiveDirName`，行为不变（config 的 dirName 不会为空），但保证前后端不会各写一套规则。
