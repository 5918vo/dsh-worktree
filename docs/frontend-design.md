# 前端设计说明

`@5318vo/dsh-worktree` · 最后更新：2026-11-20

## 1. 设计背景

本插件嵌入 the agent harness Web 的 `main` 和 `settings.section` slot，不是独立 Web 应用。前端需要在宿主既有视觉体系内，完成项目、任务、会话和 Git 验收流程的呈现。

实现入口：

- `src/client-entry.ts`：the agent harness 客户端模块注册入口。
- `src/client.ts`：factory、locale 注册和 slot 接线。
- `src/client/`：React 视图、配色、样式、国际化和数据交互的模块化实现。
- `src/client/`：按参考原型 1:1 重构的三栏看板（Rail / Stage / Inspector）。
- `src/client/styles.ts`：看板 `WORKBENCH_CSS` 与明暗 token。
- `src/client/palette.ts`：项目详情和设置页的明暗色板。
- 构建产物：`dist/client.js`。

### 约束

- 使用宿主提供的 React，不引入额外 UI 框架或图标库。
- 必须适配宿主明暗主题、宿主密度和嵌入式容器宽度。
- 会话创建、目录选择和会话打开依赖 the agent harness remote API。
- 插件不接管会话正文，审批、追问、中止和继续保持原生体验。

### 原型取舍

`docs/workbench-ui.html` 是交互原型。以下部分因宿主或后端能力暂不实现：

- 合并策略单选（merge / rebase / fast-forward）：当前后端只提供 no-ff 合并。
- 原型中的示例工具日志：插件只能读取会话投影（轮次、执行清单、上下文），不伪造工具输出。

参考原型的 Rail / Stage / Inspector 三栏结构已按 1:1 落地，包括 Rail 底部主题切换（持久化到 `dshw-board:theme`）和左右栏折叠按钮。

## 2. 设计目标

1. **先回答“当前任务是什么、下一步做什么”**：任务描述、状态和主操作优先于 Git 技术细节。
2. **降低操作歧义**：选中任务、打开会话、发布任务、验收、清理必须是不同且可预期的动作。
3. **危险操作分清层级**：合并、清理、删除不与普通操作混排，并展示明确对象和影响。
4. **密集但不拥挤**：保持开发者工具的信息密度，同时让标题、状态和辅助信息有清晰层级。
5. **嵌入式自适应**：三栏在宽容器展开，窄容器收起 Rail、把 Inspector 变成覆盖层。
6. **反馈可靠**：加载、空、失败、成功和进行中状态必须可见且不可重复提交。
7. **配色可替换**：看板颜色集中在 `WORKBENCH_CSS` 的 token，项目详情/设置页集中在 `PALETTE`。

### 非目标

- 不模拟桌面 IDE 的完整多面板布局。
- 不复制宿主已有会话页、文件树和审批 UI。
- 不为视觉表现增加额外运行时依赖。

## 3. 信息架构

```text
Worktree（.dshwd-app 三栏网格）
├─ Rail（左栏，272px）
│  ├─ Logo + 发布任务
│  ├─ 搜索（/ 或 Ctrl/Cmd+K，Esc 清空）
│  ├─ 状态过滤 pills：全部 / 待验收 / 进行中
│  ├─ 项目分组
│  │  ├─ 分组头部：项目名 + 任务数（点击查看项目详情）
│  │  └─ 任务项：标题 + 状态点 + 统计；分支 + 最近提交时间
│  └─ 底部：仓库/任务计数 + 明暗主题切换
├─ Stage（中栏，自适应）
│  ├─ 顶栏：折叠左栏 / 面包屑（项目 / 分支 → 基线）/ 折叠右栏
│  ├─ 标题区：任务名、状态 chip、基线..HEAD、更新时间、主/次操作
│  ├─ 标签页：概览 / 实时会话 / 代码改动（diff 文件数）
│  ├─ 概览：任务摘要、验收标准、验收报告导出、主操作说明
│  ├─ 实时会话：按步骤折叠的会话时间线
│  └─ 代码改动：逐文件 diff
├─ Inspector（右栏，284px）
│  ├─ 合并预检结论、目标基线、任务 HEAD
│  ├─ 技术信息：分支、会话 ID、worktree、路径
│  └─ 生命周期：未提交改动、归档/取消归档、清理
├─ 项目详情（选中项目、未选任务时占据 Stage）
│  ├─ 概览统计与待处理提示
│  ├─ 项目设置
│  └─ 删除项目
└─ 设置页（宿主 settings.section）
   ├─ 最近目录
   └─ 只读全局配置
```

## 4. 布局与响应式

### 4.1 主布局

看板根节点 `.dshwd-app` 使用 CSS Grid：

```css
grid-template-columns: 272px minmax(0, 1fr) 284px;
```

左栏 Rail、中栏 Stage、右栏 Inspector 各自独立滚动。折叠通过 `dshwd-hide-left` / `dshwd-hide-right` 把对应列宽置 `0`，并用 `grid-template-columns` 过渡动画；未选中任务时右栏自动收起。

### 4.2 容器断点

看板使用容器查询（`container: dshwboard`）判断**自身可用宽度**，而不是视口宽度：插件位于宿主侧栏右侧，页面缩放或宿主侧栏变化时视口宽度并不能代表看板宽度。

| 宽度 | 行为 |
| --- | --- |
| `> 980px` | 三栏；`272px / 自适应 / 284px` |
| `≤ 980px` | 左栏收至 `248px`；右栏默认收起，展开时以 `300px` 覆盖式抽屉出现在顶栏下方 |
| `≤ 620px` | 左栏收至 `208px`；抽屉占满 Stage 宽度 |
| 任意宽度 | 左右栏都可通过顶栏按钮折叠/展开，折叠状态不丢选中任务 |

项目详情与设置页沿用原 `dshw-scope` 的容器查询断点（双栏 → 单栏），`.dshw-scope` 自身也是容器，因此嵌入 Stage 后会按 Stage 宽度响应。

### 4.3 滚动与高度

- 外层 `height: 100%`、`min-height: 0`。
- Rail 列表、Stage 正文、Inspector 分别滚动，页面本身不承担多滚动。
- 标题和路径通过 `min-width: 0`、省略和换行规则处理溢出。
- 切换任务时 Stage 回到「概览」标签，diff 与会话状态按任务重新加载。

## 5. 视觉系统

### 5.1 配色管理

看板颜色集中定义在 `src/client/styles.ts` 的 `WORKBENCH_CSS`，以 `.dshw-board` 作用域的 CSS 变量承载：

```css
.dshw-board { --bg-canvas: #0b0b0c; --bg-rail: #070708; --bg-stage: #0b0b0c;
             --text-1: #f2f0ec; --text-2: #a9a59d; --text-3: #807c74;
             --line: rgba(242,240,236,.11);
             --accent: #e0a256; --ok: #8fbf94; --warn: #d9a93f; --err: #e0776f; }
.dshw-board[data-theme="light"] { --bg-canvas: #f8f5ef; --text-1: #17150f; ... }
```

项目详情与设置页使用 `src/client/palette.ts` 的 `PALETTE.light` / `PALETTE.dark`，由 `paletteVars()` 生成 `--dshw-*`：

```css
.dshw-scope { --dshw-bg: ...; --dshw-surface: ...; }
.dshw-dark .dshw-scope { --dshw-bg: ...; --dshw-surface: ...; }
```

两套取值必须一致（深色纸黑 + 铜色强调，浅色暖纸 + 深棕强调），改一处就要同步另一处。

`PANEL_CSS`（`src/client/styles.ts` 顶部）是叠加层，被追加到 `CSS` 与 `WORKBENCH_CSS` 末尾，用同一组规则同时约束两套 shell：按钮三档高度、chip 方标、分区自增编号、键值点线引导、左栏 34px 文本轴、统一焦点环。改版式规则优先进这里，而不是在两个样式表里各改一遍。

规则：

- 看板换色只改 `WORKBENCH_CSS` 顶部两组 token；项目详情/设置页换色只改 `PALETTE`。
- 强调色只用于：运行态、领先提交数、主操作、选中行左侧条。其余状态用降饱和的成功/警告/危险色。
- 文本三级色必须满足 AA：深色 `#807c74`、浅色 `#736f64`（均 ≥4.6:1）。
- 看板主题由 `.dshw-board[data-theme]` 控制，默认跟随宿主亮度，用户切换后写入 `localStorage` 的 `dshw-board:theme`。
- 项目详情/设置页跟随宿主 `dshw-dark` 类；该类由 `useStyles()` 根据宿主文本颜色自动维护并监听主题变化。
- 看板语义 token 包括：画布/栏底/舞台/浮层背景、悬停/激活、边框、三级文本、主 CTA、强调色、成功/警告/危险、代码块、diff 增删底色。
- 看板状态点、chip 和验收操作共用 `src/client/model.ts` 的状态映射，不单独维护近似色。

### 5.2 状态色语义

| 状态 | Tone |
| --- | --- |
| `ready`、`cleaned` | Neutral |
| `developing`、`reviewing` | Brand |
| `review` | Warning |
| `merged` | Success |
| 待审批 / 计划待审 / 待回答 | Warning |
| `broken`、操作失败 | Error |

状态同时使用文字和颜色表达，不能只靠颜色判断。左侧圆点、任务状态 chip、详情状态和项目统计共用同一套 tone 映射。

Git 状态与会话状态分开：

- `review` 只表示 worktree 有待验收的提交或未提交改动。
- 最近一轮 `turn/end.reason.kind` 为 `interrupted` 时显示「会话中断」，为 `error`/`failed` 时显示「会话异常」。
- 会话异常不改变 Git 状态，但会在任务行、任务摘要和详情横幅中同时提示，并提供打开会话入口。
- 会话正在运行时隐藏该提示，避免旧一轮的结束原因干扰当前执行。

### 5.3 字体

- 看板使用 `Inter` / 系统字体栈（`-apple-system`、`SF Pro Text`、`PingFang SC`），与参考原型保持一致；项目详情/设置页继承宿主字体。
- 页面基础字号 `13px`。
- 标题和主要操作使用 `600–650` 字重。
- Stage 正文 `13px`，辅助信息 `11–12px`，Rail 任务项标题 `12.5px`。
- 路径、分支、会话 ID 和终端内容使用等宽字体，并允许 `overflow-wrap:anywhere`。
- 不使用固定像素宽度承载唯一识别任务的标题。

### 5.4 间距、圆角和层级

- 看板常用间距：`4 / 8 / 10 / 12 / 14 / 16 / 18px`。
- 圆角统一：列表项与输入 `6px`、弹窗 `8px`、chip `4px`；不再使用 10–14px 的大圆角卡片。
- 按钮高度三档：`28px`（紧凑）、`32px`（常规）、`36px`（弹窗主操作）；图标按钮命中区不小于 `28px`。
- 选中态使用 `box-shadow: inset 1.5px 0 0` 的左侧强调条，不加边框，避免选中时内容位移。
- 不使用卡片投影；分区靠发丝线、编号和留白分隔。

### 5.5 动效

- 常规过渡 `120–150ms`。
- 待处理圆点允许轻微脉冲，但不是唯一状态信号。
- 在 `prefers-reduced-motion: reduce` 下关闭过渡、脉冲和骨架动画。

## 6. 组件规范

### 6.1 项目树头部

- 搜索框占满可用宽度，左侧有搜索图标，右侧为刷新和新增项目图标按钮。
- 搜索支持项目名、仓库路径、任务标题、分支名、标签、备注和待处理状态。
- 刷新按钮在执行中显示旋转指示器。
- 新增项目使用独立图标按钮，不创建第二个主按钮。

### 6.2 项目行

- 折叠按钮独立，提供 `aria-expanded`。
- 主体按钮包含文件夹色块、项目名和任务数量，点击主体选中项目。
- 发布任务按钮独立，不与主体按钮嵌套。
- 选中态覆盖整行主体，hover 和 focus-visible 状态分离。
- 文件夹色块使用四色循环，颜色全部来自配色表。

### 6.3 任务行

- 两行结构：
  - 第一行：状态圆点、任务标题。
  - 第二行：状态 chip、会话中断/异常 chip、优先级 chip、标签 chip、领先提交数、未提交改动数。
- 优先级只显示两端：`high` 用告警色 chip（「高」/“High”），`low` 用弱化 chip（「低」/“Low”），`normal` 不占位。行内最多显示 2 个 `#tag` chip，多出的以 `+N` 表示，悬停可看完整标签列表；无标签时整组不渲染。
- 会话最近一轮中断或失败时，状态圆点转为警告/错误色，并显示「会话中断」/「会话异常」。
- “选中任务”和“打开会话”是两个平级按钮。
- 无会话时打开按钮禁用，避免无反馈点击。
- 置顶按钮与打开按钮平级，使用 `aria-pressed` 表示状态；置顶任务在标题前显示图钉标记，按钮文案在「置顶任务 / 取消置顶」间切换。
- 置顶只是展示排序：同一项目内先按 `pinnedAt` 倒序，再按优先级（`high` > `normal` > `low`），最后按创建时间倒序；重复置顶不刷新首次置顶时间。服务端项目视图与客户端发布后的增量列表共用同一个比较函数，避免两处排序不一致。
- 停滞任务在行内显示「停滞 N 天」chip（警告色，`title` 补充最近活动时间）；「停滞」同时是一个注意力分类，行级 chip 与汇总条计数来自同一份注意力映射。
- 标题溢出省略，完整标题通过 `title` 提供。

### 6.4 任务摘要

- 顶部为项目 / 分支面包屑、任务标题和描述。
- 描述下方以列表展示验收标准（有则显示），每行一条；待验收 / 进行中等可写状态渲染为复选项，点击即标记已核对、再点取消，状态随任务记录持久化。已合并 / 已清理任务保持只读并统一显示为完成。
- 验收标准分区标题显示进度（「验收标准 · 已核对 n/total」），全部核对后显示「全部核对完成」；勾选写入进行中时复选项禁用。复选项使用 `button` + `role="checkbox"` + `aria-checked`，保留键盘 Tab / Space 操作与可见焦点环。
- 验收标准分区标题右侧固定两个 ghost mini 按钮：「复制报告」把 Markdown 报告写入剪贴板，「下载 .md」保存为 `acceptance-<id8>-<YYYYMMDD>-<HHmm>.md`。报告由当前快照与已加载的 diff 生成，内容为当前界面语言，包含标题、项目 / 分支 / 状态 / HEAD / 合并提交 / 会话 / 生成时间、标签、优先级、任务描述、验收进度、备注、提交列表、改动文件表（路径、变更类型、行数增删）与工作区统计；只含路径与计数，**不含 diff 正文**。
- 报告对各状态均降级为可读文本：无验收标准、无提交、无改动、worktree 已清理 / 找不到 merge-base / 读取失败各有一句说明；diff 被截断时明确提示。表格内的 `|` 与换行会被转义，路径不会撑破表格。
- 任一操作进行中时两个按钮同时禁用，避免重复点击或读到移动中的快照；复制失败（无剪贴板权限）或下载失败以 Toast 报错，成功同样有 Toast 反馈。回调未注入（例如 SSR 渲染或只读嵌入）时按钮不渲染。
- 元信息使用胶囊：状态、会话中断/异常、分支、领先提交数、未提交改动。
- 会话异常时在摘要下方显示警告/错误横幅，说明可能仍有未完成改动，并提供「打开会话」。
- 「打开会话」或「创建会话」是详情区唯一视觉主操作。
- 右下角显示最近活动时间。
- 待处理时显示警告横幅，可直接打开会话。
- 状态同步失败时显示错误横幅和重试入口。

### 6.4.1 任务信息（标签 / 优先级 / 备注）

- 位置固定在「任务描述」与「验收标准」之间，标题「任务信息」，使用两列 `label` / `value` 网格；窄屏自动折叠为单列。
- 标签：只读态显示 `#tag` chip，空时显示「无标签」；点击「编辑」切换为输入框（中英文逗号分隔）、保存 / 取消与 `role="alert"` 的行内错误，保存成功回到只读态。校验与发布弹窗一致：最多 8 个、每个 24 字符，超限不发请求。
- 优先级：下拉框（低 / 普通 / 高）选择后立即保存，保存中禁用；失败保留原值并抛出错误，由面板统一提示。
- 备注：只读态显示正文（保留换行）或「无备注」；编辑态为 `textarea`，`maxLength=2000`，右下角实时显示 `n/2000`；保存时 `trim`，空串即清除备注。切换任务时未保存的编辑丢弃并同步为新任务的值。
- 没有注入保存回调时（SSR / 只读嵌入）整块保持只读，不渲染编辑控件。

### 6.5 实时会话

- 卡片头部显示终端图标、标题和实时状态（工作中 / 空闲 / 待处理）。
- 未创建会话时显示空状态，说明创建后会出现的内容。
- 有会话时使用深色控制台：
  - 顶栏：状态点、模型、轮次/步数、Token 统计。
  - 主区：读取 `session.follow` 的会话历史，默认收起为每步一行。
  - 每行结构：序号、类型标签、单行摘要、变更统计、完成状态、展开箭头；摘要使用省略号截断。
  - 点击一行展开完整内容；思考和助手内容显示全文，工具显示命令/参数与结果，最大高度内滚动。
  - 思考来自 `assistant/message` 的 `reasoning` block，标题显示该 step 的持续时长（例如「持续了 4 秒」）。
  - 工具调用与 `tool/result` 按 `callId` 配对为一行：`终端 / 读取 / 编辑 / 查找 / 切换目录` 等标签，编辑类显示 `+N -M`，失败显示「执行失败」。
  - 过滤 runtime-context、time-context、skill-catalog 等系统注入消息，只保留真实用户输入。
  - 日志自动滚动到底部；用户向上滚动后暂停自动跟随。
  - 侧区：执行清单和上下文占用进度条。
- 输入区位于日志之后：四个快捷 chip 只把预设文案填入 textarea，发送前仍可编辑；`Ctrl/Cmd+Enter` 与「发送」按钮提交。chip 在无会话、等待审批 / 回答、发送中时禁用。
- 运行中的会话允许发送，并提示「会话运行中，指令会排队执行」；发送失败保留输入内容，恢复后可重试。
- 在 `≤1100px` 容器下侧区移到日志下方，日志占满宽度；`≤700px` 保持同样布局。

### 6.5.1 改动文件（待验收）

- 仅当任务处于「待验收」或「验收中」时出现，位于实时会话之后。
- 数据来自 `GET /dsh-worktree/api/task/diff?id=...`：以任务分支与基线分支的 `merge-base` 为基准，读取 worktree 工作区，覆盖已提交、未提交和未跟踪文件。
- 卡片头部展示文件数量与 `+新增 / -删除` 汇总，以及全部展开、复制 diff、刷新按钮。
- 文件行：状态字母（A/M/D/R/U）、路径（重命名显示原名）、`+N -M`（二进制显示「二进制」），点击展开逐文件 unified diff。
- diff 使用终端配色：新增行绿色底、删除行红色底、hunk 头与元信息弱化；超大 diff 由后端截断，卡片顶部提示「仅显示部分内容」。
- worktree 与分支都已不存在时显示不可用说明；相对基线无改动时显示空状态。

### 6.6 会话信息

- 使用键值行展示会话 ID、状态、模型、工作目录和最近活动。
- 会话 ID 和工作目录支持复制。
- 实际工作目录与任务 worktree 不一致时显示警告 chip。
- 未创建会话时只显示一句说明，不重复占位行。

### 6.7 验收操作

- 三个动作：切到任务分支验收、切回原分支、合并回基线。它们都会改动主仓库，因此同时判断三件事：任务状态、主仓库能否安全切换/合并、Agent 是否还在写 worktree。按钮禁用只是提示，后端执行前会用 Git 状态再次校验。
- 验收采用 **detached HEAD**：切到验收时主仓库执行 `git checkout --detach <task tip>`，台账记录 `reviewSha`、`reviewOriginalRef`、`reviewOriginalSha`；任务分支只由 worktree 持有。`reviewing` 的判定是「有 reviewSha 且主仓库 HEAD == reviewSha」，不再要求主仓库检出任务分支。
- 显示规则（「切到任务分支」与「切回原分支」互斥，只显示其中一个）：

  | 状态 | 切到任务分支验收 | 切回原分支 | 合并回基线 |
  | --- | --- | --- | --- |
  | ready / developing | 禁用「还没有可验收的提交」 | 隐藏 | 禁用「还没有可验收的提交」 |
  | review | 按条件可用 | 隐藏 | 按条件可用 |
  | reviewing | 隐藏 | 可用 | 禁用「请先切回原分支」 |
  | merged | 禁用「已合并」 | 隐藏* | 隐藏 |
  | broken | 禁用并说明异常 | 隐藏* | 禁用 |
  | cleaned | 隐藏 | 隐藏* | 隐藏 |

  \* 例外：只要主仓库当前处于该任务的验收（HEAD == reviewSha）或仍检出该任务分支，就始终显示「切回原分支」，不受 merged/broken/cleaned 优先级影响，避免用户卡在任务分支上回不去。
- 切到任务分支验收的额外条件：有领先提交（只有未提交改动时提示让 Agent 先提交）、worktree 干净、无进行中的合并/变基、同一仓库没有其他任务在验收、Agent 未运行。主仓库有未提交改动时先做预检：不冲突的改动直接带入 detached 验收；会挡住切换的改动列出文件，提供「暂存后切换 / 放弃改动后切换 / 取消」。
- 切回原分支：使用 `reviewOriginalRef` 分支 → 原分支已删则 `reviewOriginalSha`（detached）→ 最后才回基线。同样先预检：不冲突的改动直接带回；冲突改动提供「暂存后切换 / 放弃改动后切换 / 取消」，暂存会在任务详情显示「验收期间的暂存」卡片，可恢复或丢弃。若用户在验收期间自己切走了主仓库（HEAD != reviewSha 或已有分支名），只清除验收记录、不强切。Agent 运行中也允许切回。
- 合并回基线的额外条件：有领先提交且 worktree 无未提交改动、主仓库当前就在基线分支（不自动切换）、主仓库干净、无进行中的合并、Agent 未运行、冲突预检通过。主仓库不在基线分支时，提供显式的「切到基线分支并合并」：确认后临时切到基线执行合并，可选合并后切回原分支；若基线分支已被其他 worktree 检出则拒绝。
- 禁用原因直接写在按钮下方，不只放在悬停提示；每条原因尽量配一个下一步（打开会话、切到该任务、同步基线）。
- 同一主仓库任一 Git 操作执行期间，该项目下所有任务的三个按钮都禁用并显示动作名称；后端不通过时返回具体原因并刷新详情。
- 合并通过页面内确认弹窗执行，展示分支、基线、领先提交和未提交改动。
- 已合并（或已合并后清理）的任务：主操作为「基于此任务继续」，「打开会话」降为次级；继续会打开发布弹窗并预填标题（原标题加「（续）」）、项目默认基线和「关联前序任务」，描述留空。
- 已合并任务在分支上又有新提交时，显示「已合并 · 之后有 N 个新提交」横幅，提供「再次合并」与「基于此任务继续」两个动作；此时验收切换与合并按待验收处理。

### 6.7.1 后续任务与任务关系

- 「基于此任务继续」沿用原任务所属项目；默认基线取**原任务实际合并到的分支**（不随项目默认基线变化而静默替换），起点是该基线最新的本地提交。
- 新任务分支始终用新任务 ID 重新生成（如 `dsh-wt/<新id8>`），不复用旧任务分支；新任务记录 `parentId`。
- 发布弹窗默认显示原合并目标作为基线，允许改选；发布时校验所选基线是否包含前序已合并成果，不包含则提示「所选基线未包含前序成果，请选择原合并目标，或改为普通任务」，并提供「作为普通任务发布」选项。
- 前序分支在合并后仍有未合并提交时，继续弹窗显式让用户选择「仅基于已合并成果继续」（默认，不带入新提交）或「迁移合并后的新增改动」（把这些提交列进首条提示词，由 Agent 用 `git cherry-pick <mergeBase>..<branch>` 带入并处理冲突）。
- 任务详情提供「任务关系」卡片：向前链接前序任务，向后列出后续任务，均可点击跳转。
- 发布后续任务成功后，如果前序 worktree 仍存在，弹出「清理前序任务的 worktree」确认（默认保留，不自动清理）；清理只删除目录，不删分支与提交。

### 6.8 Worktree 与主仓库

- 顶部 chip 显示 worktree 状态：正常 / 已清理 / 目录缺失 / 已合并。
- Worktree 区展示路径、当前分支、领先提交和未提交改动。
- 主仓库区展示仓库路径、当前分支、验收前分支和未提交改动。
- 路径、分支均提供复制按钮。
- worktree 已清理时隐藏已失效的分支和改动行，只保留路径记录和说明。

### 6.9 危险操作

- 单独卡片，使用危险色边框和标题。
- 清理 worktree 和删除记录是两个不同动作：
  - 清理会删除目录，可勾选同时删除分支。
  - 删除记录只移除看板条目。
- 清理确认弹窗列出将被删除的路径、未提交改动数量、强制清理和删除分支选项。
- 删除分支默认只删除已合并分支；未合并分支会被拒绝并提示「强制删除分支」（丢弃未合并提交），且在删除 worktree 之前先做该校验，避免半清理状态。
- 删除记录确认弹窗展示分支、worktree 和状态，并说明不可撤销。

### 6.10 项目详情

- 页头：文件夹图标、项目名、仓库路径、任务数量、发布任务和更多操作。
- 概览卡片：
  - 四个统计：任务总数、进行中、待验收、已合并。
  - 待处理任务汇总提示，可跳转到第一个待处理任务。
  - 仓库、基线分支、分支前缀和 Worktree 根目录。
  - 「项目验收报告」卡片：说明文字 + 「复制」「下载」两个 ghost 按钮，报告内容与单任务报告同源纯函数；包含项目元数据、按状态统计、任务表（状态 / 分支 / 进度 / 优先级 / 标签 / 最近活动）与逐任务块（状态、分支、合并提交、验收标准、备注）。文件名 `project-<slug>-<YYYYMMDD>-<HHmm>.md`，`slug` 只保留字母数字并截断到 32 字符。导出与复制都在本地完成，不发起网络请求。
- 项目设置：
  - 项目名、默认基线分支、分支前缀、Worktree 根目录（`~`/绝对路径放在仓库外，相对路径保留仓库内布局）。
  - 「验收标准未全部核对时禁止合并」复选框：保存时写为 `mergeGate: 'criteria'`，取消则写 `off`；帮助文本说明只影响合并，没有验收标准的任务不受影响。
  - 保存中禁用提交，保存成功后显示状态文字。
- 删除项目：
  - 有任务时必须勾选「连同任务一起删除」，否则确认按钮禁用。
  - 明确说明磁盘上的仓库、worktree 和提交不会被删除。

### 6.11 设置页

- 页头显示标题和说明。
- 验收标准库：维护可复用的验收标准，支持添加和移除，供发布任务时勾选。
- 发布模板：列出模板名称、标题与验收标准，支持新建、编辑、删除；编辑器包含名称、标题、描述与「每行一条」的验收标准文本域。删除复用确认弹窗，保存或删除后以 Toast 反馈并刷新列表。
- 最近目录：展示路径，支持复制和清空。
- 清空最近目录通过确认弹窗执行。
- 全局配置为只读，来源是宿主配置。

### 6.12 表单

- 所有原生控件必须与 `<label>` 关联。
- 必填项显示 `*`，并向控件传递 `aria-required`。
- 字段错误通过 `aria-invalid`、`aria-describedby` 和 `role="alert"` 关联。
- 错误后聚焦第一个出错字段。
- 输入框、下拉框最小高度 `36px`。
- 分支加载区分加载、成功和失败；失败时允许手动输入或重试。

### 6.13 弹窗

- 使用 `role="dialog"`、`aria-modal="true"`、`aria-labelledby`。
- 打开时优先聚焦 `data-autofocus` 元素，否则聚焦首个表单控件。
- Tab / Shift+Tab 在弹窗内循环。
- Escape 关闭；忙碌时禁止关闭。
- 关闭后将焦点恢复到触发元素。
- 页脚操作固定与正文分离；危险弹窗默认聚焦取消。
- 操作失败时错误显示在当前弹窗内，不要求用户关闭弹窗后再找原因。

### 6.14 按钮

| 类型 | 用途 |
| --- | --- |
| Primary | 页面唯一主要动作，例如打开/创建会话、保存、发布 |
| Secondary | 常规操作，例如切分支、合并、取消 |
| Danger | 清理、删除项目或任务 |
| Icon | 刷新、新增项目、折叠、关闭、打开会话、复制 |
| Ghost | 低权重内联操作 |

危险按钮使用错误色边框和文字，不使用大面积红色填充，避免视觉噪声。

### 6.15 Toast

- 用于复制成功/失败、刷新完成、发布、合并、清理和删除结果。
- 固定在底部居中，`role="status"`、`aria-live="polite"`。
- 约 `2.8s` 后自动消失，不阻塞操作。
- 表单级错误仍使用内联错误，不用 Toast 替代字段提示。

### 6.16 空、加载和错误状态

- 无项目：`暂无项目` + 新增项目入口。
- 搜索无结果：`没有匹配的项目` + 清除搜索。
- 无选中任务：`未选择任务`。
- 列表加载：骨架屏。
- 分支加载：显示加载指示器，未取得分支前禁止提交。
- 分支失败：显示失败说明和重试，同时允许手动输入。
- 操作失败：使用 `role="alert"`；操作成功：使用 `role="status"`。

## 7. 关键交互

### 7.1 搜索与快捷键

- 输入即过滤，不需要提交。
- 搜索匹配项目名、仓库路径、任务标题、分支名、标签、备注和待处理状态。
- `/` 或 `Ctrl/Cmd+K` 聚焦搜索，仅在焦点位于插件内部时生效，避免劫持宿主聊天输入。
- `Esc` 清空搜索。

### 7.2 新增项目

- 目标目录、默认基线分支为必填。
- 目录选择器使用同步 ref 锁，鼠标按下触发，防止首次点击被焦点消耗或连续点击打开多个窗口。
- 切换目录时立即清空旧分支，防止跨仓库使用错误基线。
- 分支请求使用 `150ms` 防抖。
- 默认基线分支使用可搜索下拉（与发布任务弹窗同一组件），可按名称过滤。
- 分支为空、加载中或路径为空时禁用提交。
- 弹窗不显示历史目录；设置页仍保留最近目录管理。

### 7.3 发布任务

- 自动任务分支格式为 `<branchPrefix><id8>`，例如 `dsh-wt/b92e5f2a`。
- 任务标题和描述为必填。
- 自定义分支名只接受 ASCII 字符。
- 主表单包含「立即执行」表单项，以「是 / 否」单选呈现，默认选中「是」；高级选项包含模型选择与自定义任务分支。
- 高级选项的模型选择使用与官方会话模型下拉同一份数据源（`session.modelCatalog()`，按提供方分组的目录）：支持按名称 / ID 过滤、上下方向键与回车选择，可切回「默认模型」，不选时使用默认模型。
- 所选 provider / model 随任务持久化；会话创建后、首条指令发送前通过 `session.selectModel` 应用，确保首个请求即使用该模型；从「创建会话 / 启动任务」或看板自动绑定时同样生效。
- 基线分支为可搜索下拉：打开后输入即按名称过滤（大小写不敏感），支持上下方向键移动、回车选中、Esc 仅关闭列表而不关闭弹窗；无匹配时显示「没有匹配的分支」。列表在字段下方就地展开，避免被弹窗滚动容器裁剪。新增项目、项目设置的基线字段复用同一组件。
- 底部不再展示分支/目录预览，命名规则由分支规则提示说明。
- 验收标准为可选多行字段：可从全局验收标准库勾选，也可临时手动补充（每行一条）；空行和重复项在保存前丢弃，全部为空时不落库、不展示。
- 模板选择器位于标题之后；选中模板会填充标题、描述与验收标准。模板标准中存在于全局库的条目进入勾选项，其余写入手动标准；不修改项目、基线、自定义分支、模型或「立即执行」。
- 没有模板时选择器收起，只显示去设置页创建的提示，不占额外表单行。
- 验收标准写入首条提示词（列在描述后，并要求结束前逐条说明是否满足、未满足的说明原因），不使用插件接管会话内容的方式。
- 发布按钮使用同步锁，重复点击只提交一次。
- UI 发布由客户端自行绑定会话；HTTP 发布不会触发工作台的自动绑定，避免手动绑定和轮询同时创建两个会话。
- 选择「是」时，客户端在绑定会话后显式发送 `firstPrompt`；不依赖服务端的 `startOnBind`（UI 发布带 `autoBind:false`，该字段为 `false`）。
- 首条指令发送失败时不解绑、不绑定空白会话，任务保持「待开始」，可稍后重新创建会话。
- 发布成功后刷新工作台；如果会话创建失败，任务仍保留，并用错误 Toast 提示。
- 从已合并任务继续时，弹窗预填标题与关联前序任务并携带 `parentId`；前序未合并或改动不在基线时，错误在弹窗内显示。

### 7.4 打开或创建会话

- 已有会话：详情主按钮直接打开原生会话。
- 没有会话：主按钮创建会话并打开，创建后发送 `firstPrompt`。
- 已绑定但会话为空（宿主 `sessionListMetadata.blank`）时，详情主按钮显示「启动任务」，向已有会话补发 `firstPrompt`，成功后打开会话。
- 会话被删除后，任务保留，可再次创建会话。

### 7.5 验收、合并与清理

- 合并前展示分支、基线、领先提交和未提交改动。
- 合并确认弹窗列出该任务的验收进度（已核对 n/total）。项目开启合并门禁且仍有未核对项时，预检返回 `criteria-incomplete` 阻断项，合并按钮禁用并写明还差几项；项目未开启时仍只提示、不阻断。
- 清理前展示 worktree 路径、未提交改动、强制清理和删除分支选项。
- `force`、`deleteBranch` 状态随任务 ID 重置，不跨任务继承。
- 普通操作和危险操作分区。
- 执行中的按钮显示具体动作，其他按钮禁用，避免重复提交。
- 操作成功后自动刷新状态并显示 Toast。
- 合并按钮要求冲突预检通过（有真实冲突、预检失败或不支持时禁用），把冲突挡在点「合并」之前，而不是合并失败后才报错。
- 主仓库不在基线分支时，合并按钮变为「切到基线分支并合并」：弹窗说明会临时切换到基线；合并后默认切回原分支，可取消勾选；切换前校验主仓库干净、无进行中操作，且基线未被其他 worktree 检出。
- Git 写操作（合并/清理/切分支）使用长超时，慢钩子（如 eslint）不会让客户端提前报错；同一主仓库的 Git 写操作串行，重复点击返回「主仓库正在执行…」；操作失败也会触发看板刷新，避免状态滞后。

### 7.6 基线预检与同步

- 任务详情每 15 秒请求 `task/merge-preview`；基线有新提交时显示附加标记，不改变任务状态。
- 只要基线领先基线分叉点，就执行 `git merge-tree --write-tree` 真实预检；不再只在文件路径重叠时才预检。
- 预检到真实冲突时显示「预计冲突 · N 个文件」，**合并按钮直接禁用**；预检未完成、失败或 Git < 2.38 不支持时同样阻止合并并说明原因。
- 合并确认弹窗打开时重新预检：
  - 无冲突且预检通过：允许合并，列出重叠文件作为风险提示。
  - 有冲突或无法预检：禁用「合并」，并显示「让 Agent 同步基线」。
- 预检返回 `expectedTip` / `expectedBase`；合并必须带回这两个 SHA，执行前任一不一致直接 409「任务分支或基线已变化，请重新预检」。
- 「让 Agent 同步基线」只在用户点击后向当前会话发送预设消息，插件不会自动在会话里插入提醒。
- 同步消息包含基线分支、任务分支和预检文件，并要求 Agent 按任务提示词中的「同步基线」规则处理。
- 服务端 `merge` 在真正执行 `git merge` 前会再做一次同样的冲突预检；预检不通过就返回 409 并阻止操作，**不会把主仓库留在合并中**，避免已知冲突走到合并失败。

### 7.7 删除任务与项目

- 删除任务记录不影响磁盘上的 worktree 和分支。
- 删除项目时，如果还有任务，必须显式勾选同时删除任务记录，否则确认按钮禁用。
- 删除后自动清理选中状态，回到仍有内容的项目或空详情。

### 7.7 刷新与轮询

- 工作台每 4 秒刷新项目视图，页面不可见时暂停。
- 手动刷新按钮显示独立进行中状态，并在完成后提示。
- 会话投影每 4 秒拉取一次，用于实时会话卡片。

### 7.8 会话快捷指令

- 快捷指令只负责生成文本，不直接调用宿主接口；发送统一走与「启动任务」相同的 `sendSessionPrompt` 路径。
- 无会话、等待审批 / 回答时禁用并给出原因；发送中显示进行状态，避免重复提交。
- 会话运行中仍可发送，文案说明指令会排队；失败时保留输入并提示，不自动重试。

## 8. 可访问性

必须保持：

- 键盘可到达全部交互元素。
- 可见的 `:focus-visible` 焦点环。
- 原生按钮语义，不使用带点击事件的 `span` 代替按钮。
- 图标按钮具有 `aria-label` 和 `title`。
- 状态不仅依赖颜色。
- 表单标签、必填、错误和帮助文本建立可访问关联。
- 弹窗焦点圈定和恢复。
- 异步反馈使用 `alert` / `status` live region。
- 支持减少动态效果。
- 正文和辅助文字在明暗主题下满足可读性，实际对比度需在 the agent harness 宿主中复核。

## 9. 文案原则

- 面向用户，不暴露内部实现文件名、配置键或开发步骤。
- 空状态使用简短状态，不写“点右上角……”式操作说明。
- 说明文字优先通过 placeholder、字段标签或状态反馈表达。
- 操作按钮使用动词，例如「打开会话」「创建会话」「保存」「清理」。
- 危险操作明确对象和影响，不使用模糊的「确定吗」。
- 中英文界面均使用同一套语义 key，不在组件内硬编码中文。
- 错误信息说明原因和可执行的下一步，不只显示“失败”。

## 10. 代码组织与扩展原则

当前 UI 已按职责拆分到 `src/client/`，`src/client.ts` 只保留宿主模块注册、factory 和 slot 接线。后续扩展遵循：

- 新组件优先复用 `src/client/primitives.ts` 的 `Btn`、`IconBtn`、`Chip`、`Dot`、`Card`、`CardHead`、`KV`、`Field`、`Modal`、`Banner`、`Stat`、`Toast`。
- 看板新颜色必须加入 `src/client/styles.ts` 的 `WORKBENCH_CSS` token；项目详情/设置页新颜色必须加入 `src/client/palette.ts` 的 `PALETTE`，组件里不写十六进制、`rgb()` 或命名颜色。
- 新状态必须进入 `src/client/status.ts` 的 `STATUS_TONE`，不能单独定义近似色。
- 新文案必须加入 `locale/en.json` 和 `locale/zh.json`；`src/client/i18n.ts` 直接引用这两个文件，不再维护第二份字典。
- 新表单必须使用 `Field` 或等价的 label / error / aria 关联。
- 弹窗必须复用 `Modal`，不能复制焦点管理；需要“取消 + 确认”时优先复用统一 footer 结构。
- 复制、刷新、操作结果在看板走 `board.ts` 的轻量 Toast 状态，在项目详情/设置页走 `useToast` + `Toast`，不要重复实现计时器。
- 请求统一走 `src/client/context.ts` 的 `getJson` / `post`，它们带 token 刷新、12s 超时和重试语义。
- 组件内不要直接 `import React from 'react'`：宿主通过 `factory(require)` 注入 React，统一从 `src/client/ui.ts` 读取代理。
- 看板样式只改 `src/client/styles.ts` 的 `WORKBENCH_CSS`，遵循 `dshwd-*` 前缀和 `.dshw-board` 作用域；项目详情/设置页样式改同一文件的 `CSS`。主题探测和 `<style>` 单例引用计数在 `ui.ts`。
- 修改交互后同时更新本文件和 `README.md`。

## 12. 已知限制

- 历史中文任务分支不会自动重命名，避免破坏已有 worktree 和合并记录。
- 分支列表依赖本地 `git` 命令，超大仓库或网络盘仓库可能明显慢于本地磁盘。
- 目录选择器由 the agent harness / 操作系统提供，无法在当前前端内自定义其样式。
- 合并策略由后端固定为 no-ff，前端不提供策略选择。
- 实时会话只能展示宿主投影提供的轮次、执行清单和上下文，不包含完整工具日志。
- 看板新界面暂未接入「会话中断 / 会话异常」行内提示和验收按钮的禁用原因说明，操作失败目前统一以 Toast 呈现。
- 当前没有自动化 UI 测试，交互验收以类型检查、构建和真实 the agent harness 浏览器测试为主。
- 设置页仍保留最近目录管理，与新增项目表单的历史目录选择是两套不同入口。
- 后续任务不会在发布时物理迁移前序分支合并后新增的提交，而是在首条指令中交给 Agent 用 cherry-pick 带入并处理冲突。
