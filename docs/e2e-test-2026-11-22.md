### 不修项（有明确理由）

- 新增项目后左栏 1–2s 延迟：已触发 `refresh()`，属于 projects 快照/API 延迟。
- UI primitives 缺失警告：宿主版本未导出 `Button` / `DisclosureRow` / `Input`，插件按设计回退内置控件。
- 发布弹窗保留草稿后再次关闭不再确认：重开时表单基线就是草稿，未改动时不应再确认。
- 验收 detached 行为本身：`3bf36a0` 刻意采用 SHA 锁定的 detached 验收，避免主仓库与 worktree 同时检出同一分支；本轮回退为「保留行为 + 明确提示 + 文档对齐」。

## 五、交付阶段发现（非 E2E 用例）

- **从 linked worktree 推送时 pre-push hook 注入 `GIT_DIR`**：Git 会把 `GIT_DIR` 传给 hook，hook 里的 `npm run verify` 再传给测试进程；测试创建临时仓库时继承该变量，`git init/config/add/commit` 实际写进了调用方仓库。后果：共享 `core.bare` 与 `user.*` 被改写、本地分支和 `refs/heads/*` 出现测试提交（`init` / `feat: a`）、临时 worktree 注册残留。
  - 本机 hook 已修复：执行 `npm run verify` 前 `unset` 仓库定向变量。
  - 根因修复（测试运行器与 git 助手剥离 `GIT_DIR` / `GIT_WORK_TREE` / `GIT_INDEX_FILE` 等）已在 `feat/acceptance-checklist`（`e69b851`）落地，见 PR #6。
  - 已恢复共享配置、被改写的本地分支，并清理测试创建的分支与临时 worktree 注册；恢复后 `npm run verify` 通过（当时 276/276）。
